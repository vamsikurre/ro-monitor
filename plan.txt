============================================================
1. PROJECT GOAL
============================================================

Build a reliable local RO plant monitoring system using:

- ESP32S as the main HUB
- Arduino Nano nodes for remote tank-level measurement
- RS485/Modbus-style communication between the HUB and tank nodes
- Ultrasonic waterproof sensors for tank levels
- Optically isolated inputs for 240V AC signals
- PC817 isolation for low-voltage/dry-contact signals
- SHT30 temperature/humidity sensor
- WiFi connectivity from the ESP32 HUB
- A local monitoring web interface
- Architecture that can later be extended for IoT/cloud integration

The system should be designed as an industrial-style monitoring system rather than a hobby/demo sketch.

Reliability, electrical isolation, fault detection, watchdog recovery, communication timeout handling, and safe startup behavior are important.

============================================================
2. HARDWARE ARCHITECTURE
============================================================

PHASE 1 = HUB

The HUB will be installed near the RO controller.

Main controller:

- ESP32S 38-pin development board
- WiFi + Bluetooth
- ESP32 is the main processor and communication gateway

Power:

- Hi-Link HLK-20M12
- Input: 100–240V AC
- Output: 12V DC
- Rated power: 20W
- This is the main 12V supply for the system

The HUB will use a 12V -> 5V buck converter for the ESP32 and 5V peripherals.

The 12V supply will also be distributed through CAT5e to remote tank modules.

Do NOT use the previously considered HLK-5M12 5W module.

The selected main PSU is:

HLK-20M12, 12V / 20W.

============================================================
3. HUB INPUTS
============================================================

The following signals are planned for the HUB.

A) HPP

HPP = High Pressure Pump signal.

The signal is 240V AC.

Interface:

240V AC -> appropriate AC opto-isolator -> ESP32 GPIO

The firmware must treat this as an isolated digital input.

B) RWP

RWP = Raw Water Pump signal.

The signal is 240V AC.

Interface:

240V AC -> appropriate AC opto-isolator -> ESP32 GPIO

Again, this must be electrically isolated from the ESP32.

IMPORTANT:

Do not connect 240V directly to the ESP32.

Do not assume the exact controller terminal until the photographs in /images have been inspected.

C) TWT FLOAT

TWT has a float switch/digital contact.

Interface:

TWT float -> PC817 optocoupler -> ESP32 GPIO

Determine from the actual hardware whether the float is NO/NC and design the firmware so that the logical state can be configured rather than hard-coded.

D) RL1 / RL2

RL1 and RL2 are relay/status signals.

Use PC817 optocoupler isolation where appropriate.

The software should represent these as named status inputs rather than generic GPIOs.

Example:

RL1_STATUS
RL2_STATUS

The exact meaning of RL1/RL2 must be determined from the actual controller/photos/documentation rather than guessed.

5. DOSING TANK
============================================================

The dosing tank requires a level measurement.

Use an ultrasonic waterproof sensor.

The sensor I purchased is an industrial-style waterproof ultrasonic sensor with:

- 5V supply
- Trigger
- Echo
- GND
- approximately 0.3m–3m stated range
- approximately 25cm blind zone
- approximately 40kHz operation
- approximately 0.5cm stated resolution

It is similar electrically to an HC-SR04 but uses a waterproof probe.

The dosing tank sensor will initially be connected to the HUB if practical.

The software must convert measured distance into:

- distance_mm
- level_mm
- level_percent

The tank geometry must be configurable rather than hard-coded.

Allow configuration for:

- tank height
- sensor mounting offset
- minimum measurable distance
- maximum measurable distance
- empty level
- full level

Because the sensor has a blind zone, reject impossible measurements.

Do not blindly accept 0cm or out-of-range readings.

============================================================
7. CAT5e POWER + COMMUNICATION
============================================================

The remote tank modules are only approximately 5–10 meters from the RO controller/HUB, with the tanks approximately one slab above.

I have CAT5e cable available and intend to use it.

12V DC will be sent from the HUB to the remote tank module through the CAT5e cable.

At the remote tank module:

12V -> 5V buck converter -> Arduino Nano + ultrasonic sensor + RS485 transceiver

The CAT5e cable will also carry RS485 communication.

Use twisted pairs intelligently.

Prefer:

Pair 1:
RS485 A / RS485 B

Pair 2:
12V / GND

Additional conductors/pairs may be used as appropriate.

Document the exact proposed CAT5e pin/pair assignment.

Do not use Ethernet networking over this cable.

It is simply being used as convenient multi-conductor cable for:

- 12V power
- GND
- RS485 differential communication

The 5–10 meter distance is short for RS485, so the design should be robust at this distance.

============================================================
8. RS485 NETWORK
============================================================

There will be ONE RS485 bus connected to the ESP32 HUB.

Multiple Arduino Nano tank nodes will share the same bus.

Example:

ESP32 HUB
    |
    +---- RS485 ---- Tank Node 1 (Dosing)
    |
    +---- RS485 ---- Tank Node 2 (Raw Water)
    |
    +---- RS485 ---- Tank Node 3 (Treated Water)

This must NOT be implemented as three separate UART interfaces unless there is a compelling reason.

Use a single RS485 bus with device addressing.

Each tank node must have a unique address.

Example:

0x01 = DOSING_TANK
0x02 = RAW_WATER_TANK
0x03 = TREATED_WATER_TANK

Reserve additional addresses for future nodes.

Use a simple deterministic request/response protocol, preferably Modbus RTU-compatible or a clearly documented lightweight protocol.

The architecture should make it easy to migrate to standard Modbus RTU later.

============================================================
10. RS485 TERMINATION / TOPOLOGY
============================================================

Use proper RS485 bus topology.

Do NOT create a star network.

The preferred physical topology is:

HUB ---- Node 1 ---- Node 2 ---- Node 3

or another daisy-chain arrangement following the actual cable routing.

Termination should be used only at the two physical ends of the RS485 bus.

The firmware/project documentation must explain:

- A/B polarity
- termination
- common ground/reference
- cable pair assignment
- node addressing
- communication timeout
- retry behavior

Because the cable distance is short, do not over-engineer the communication speed.

A conservative baud rate such as 9600 or 19200 is acceptable.

Reliability is more important than speed.

11. ARDUINO NANO TANK NODE
============================================================

Each Nano node should perform the following:

1. Boot
2. Initialize ultrasonic sensor
3. Initialize RS485
4. Measure tank level periodically
5. Filter invalid readings
6. Calculate level percentage
7. Respond to HUB requests
8. Report sensor faults
9. Continue operating even if HUB communication is temporarily lost

The Nano should NOT depend on the HUB being available to perform measurements.

Each node should maintain its own sensor state.

Example status:

OK
SENSOR_ERROR
OUT_OF_RANGE
NO_ECHO
COMMUNICATION_ERROR

The HUB should be able to distinguish:

"tank is empty"

from

"tank sensor is not responding."

============================================================
12. ULTRASONIC MEASUREMENT
============================================================

Implement robust measurement filtering.

Do not use one raw ultrasonic reading directly as the displayed level.

Suggested approach:

- Take multiple samples
- Reject invalid/out-of-range samples
- Apply median filtering
- Optionally apply moving average/exponential smoothing
- Detect sudden impossible changes
- Track sensor timeout

Make all filtering parameters configurable.

Example:

ULTRASONIC_SAMPLE_COUNT
ULTRASONIC_TIMEOUT_US
LEVEL_FILTER_ALPHA
MAX_LEVEL_CHANGE_PER_UPDATE

The system should produce stable readings without introducing excessive delay.

21. ELECTRICAL SAFETY
============================================================

This system interfaces with 240V AC equipment.

Treat all mains interfaces as dangerous.

Never connect 240V directly to:

- ESP32
- Arduino Nano
- SHT30
- RS485 transceiver
- ultrasonic sensor

Use appropriate opto-isolation.

Keep SELV electronics physically separated from mains wiring.

Use suitable fusing, insulation, enclosure, cable management and terminal blocks.

Do not implement any mains switching/control functionality until the actual controller circuitry and required isolation have been verified.

For the first implementation, prioritize MONITORING.

============================================================

- node address
- command
- response
- payload
- checksum/CRC
- timeout
- retry

Example commands:

READ_STATUS
READ_LEVEL
READ_SENSOR
PING
GET_CONFIG
SET_CONFIG

The HUB should poll nodes sequentially.

Example:

HUB -> Node 1: READ_STATUS
Node 1 -> HUB: response

HUB -> Node 2: READ_STATUS

HUB -> Node 3: READ_STATUS
